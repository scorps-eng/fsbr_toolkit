# FSBR Toolkit

Веб-инструмент (чистый PHP) для загрузки отчётов ФСБР.

## Возможности

1. **Проверка отчёта** — турнирные протоколы (пары, команды, индивидуал) и **клубные МБ**
2. **Расчёт РО / ПБ / МБ** — только для турниров (клубные МБ пропускают)
3. **SQL** — вставка в `tourn_header` + `tourn_pair` / `tourn_team` / `tourn_ind` / сессии; клубные — `type=5`
4. **История** — лог выполненных SQL

## Установка

1. Скопировать на PHP-хостинг (PHP 8.0+, расширение `mysqli`, для xlsx — `zip`)
2. Создать учётки БД: выполнить `db_setup.sql` (три учётки с минимальными правами)
3. `config.example.php` → `config.php`: доступ к БД, `auth_user` и `auth_pass_hash`
   (хеш: `php tools/hash_password.php`). **Пока пароль не задан, доступ закрыт.**
4. Открыть `index.php`, войти.

`results` скриптами раз в месяц — toolkit туда не пишет (у учётки записи нет прав на эту таблицу).

## Замена существующего турнира (поле tourn_id)

- Заменяются только данные того же типа (type); результаты (`results`) не трогаются.
- Из старой записи сохраняются `next_id`, `note`, `parent`, а также `prev_id`, `stream`, `champ_t`, `status`, `city_id`, если поля в форме пустые.
- Заголовки сессий старой версии удаляются всегда.
- `prev_id`: нельзя указать сам турнир или сессию; если у предыдущего турнира уже есть другой следующий или он датирован не раньше нового — нужно подтверждение галочкой.

## Клубные МБ

Игроки с несовпавшим именем, а также «умершие» и «неактивные» в SQL по умолчанию не попадают — их можно включить галочками на вкладке «SQL».

**Клубные МБ за месяц одним архивом.** На вкладке «Проверка» загрузите `.zip` со всеми файлами месяца (или один `.json`) —
всё собирается автоматически в один турнир «{Город} клубный» за период с 1-го по последнее число месяца.
В архиве понимаются: JSON с парами (`name1/id1/name2/id2/mb`, UTF-8/UTF-16; МБ пары получает каждый игрок),
таблицы `.xls/.xlsx` «ФИ / id / МБ» (если над колонкой МБ есть «сумма…» — берётся она, иначе суммируются все колонки МБ)
и официальные «Отчет по МБ». Скрытые строки и столбцы в таблицах игнорируются (в турнирных протоколах — только строки, и если в них были значения, выводится предупреждение). Лишние файлы и служебные папки игнорируются, имена в кодировке cp866 распознаются.
Месяц определяется по датам в JSON, по именам файлов вида `…260907…` (ггммдд), по заголовку «сумма сентябрь 2026»
или вводится вручную; файлы за разные месяцы отклоняются. МБ игрока суммируются по id. Город берётся из JSON
(если не распознан — выбирается из списка, файлы заново загружать не нужно). Перед SQL показывается список файлов и сумм.

## Анкеты игроков

**Публичная форма** (`questionnaire.php`):
- e-mail подтверждается кодом из письма (6 цифр, 15 минут, 5 попыток, пауза 60 с, лимиты по IP и адресу); без подтверждения анкета не отправляется. Нужен `mail_from` в `config.php`; `mail_transport` = `mail` (PHP `mail()`) или `file` (письма пишутся в `data/mail_outbox.json.php` — только для проверки).
- при обновлении данных человек вводит из прошлой анкеты дату рождения, последние 4 цифры телефона и e-mail; результат сверки (`ok`/`weak`/`failed`/`none`) сохраняется в `aux_questionaries.verify_status` и ему не показывается.
- при обновлении уходят только явно изменённые поля.

**Вкладка «Анкеты»** (вход обязателен): список (ожидают / приняты / отклонены) → анкета в трёх колонках: заполненная · предыдущая (или текущие данные из базы) · новая (редактируемая, изменения подсвечены). Для нового игрока показываются возможные совпадения с ID (игроки в базе, анкеты, ожидающие добавления); нужно выбрать существующего или отметить «Выдать новый ID». Кнопка «Сформировать SQL» показывает транзакцию, выполнение — по подтверждению, одноразовым ключом, с откатом при ошибке. Анкету можно отклонить с причиной.

Перед первым использованием выполните раздел 4 из `db_setup.sql` (колонки статуса и права).

## Безопасность

- **Вход** по логину/паролю (`password_verify`), блокировка после 5 неудачных попыток на 15 минут по IP,
  автовыход по бездействию, cookie `HttpOnly` + `SameSite=Lax` (+ `Secure` на HTTPS). Работайте только по HTTPS.
- **CSRF**: все POST-формы несут токен, запросы без него отклоняются (403).
- **Три учётки БД**: `ro` — чтение; `rw` — только выполнение SQL, права только на таблицы турниров;
  `q` — анкета. Старая схема с одной парой `db_user/db_pass` работает, но так защита слабее.
- **Выполнение SQL**: только SQL, сформированный приложением в этой сессии (правка вручную
  отключена; включается `allow_edit_sql`), с одноразовым ключом (повтор POST не создаёт дубль),
  с откатом при ошибке.
- Каталоги `data/` и `tools/` закрыты `.htaccess` (для nginx закройте их в конфиге сервера).
- `questionnaire.php` — отдельная публичная форма (вход не требуется). Её поиск отдаёт телефон и e-mail
  найденных игроков: если форма не должна быть публичной, закройте её на уровне сервера или добавьте `auth_require()`.
